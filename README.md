# CivBench

CivBench 是一个以城市长期发展为背景的 AI 综合能力评测项目。模型需要在连续的模拟年份中完成代码、科研与工程任务，并将通过验收的成果用于城市建设和运行，承担预算、资源、工期和后续维护的影响。

本仓库仅提供项目介绍。全部实现、题目、数据、设计文档、测试和历史开发资料统一保存在 [CivBench-Dev](https://github.com/Alpaca233114514/CivBench-Dev)；该开发仓库当前为私有仓库，访问需要授权。

## 评测方式

- **长期决策**：支持 30、60、100 年三个档位，默认 60 年；开局锁定年限，逐年观察、决策和结算。
- **渐进披露**：模型通过 CLI 获取当前简报和按需查询的信息，未来事件、隐藏测试和参考答案不进入正常作答流程。
- **真实代码交付**：在独立项目仓库中实现题目，经历首交付、适应和维护三个阶段，由控制器冻结版本并独立验收。
- **隔离执行与预检**：候选代码在禁网、限内存/CPU/进程数与只读挂载的隔离环境中运行，默认使用本地 Linux/WSL Bubblewrap + systemd，也支持可选的 Docker Linux 容器后端，均不回退宿主执行；开局前通过 `runtime-status` 对依赖及适配器正反例做预检。
- **成果用于城市**：符合条件的冻结代码可生成城市运行提案（覆盖 13 类科研/工程运行接口），实际采用后承担对应的行动、资金、资源与工期。
- **可追溯交卷**：保留逐年决策、逐冻结交付验收摘要（区分通过、未尝试/弃答与执行器故障）、评分和导出记录；历史批次（含 `0.2.x` 与 `0.1.x`）沿用原归档引擎只读路由，不迁移、不重评分。

## 任务范围与科技树（0.3.0-dev）

当前开发版本为 **0.3.0-dev**。全树保持 **52 个科技节点**，重组为 **6 大类、14 子类**，沿 `T1 → T4` 保持层级单调递增（消除前置难度、阶段与解锁费用倒挂）。

| 大类 | 子类 | 节点数 | 主要题源与开源许可证 |
| --- | --- | ---: | --- |
| **计算机学** | 算法工程、数据系统 | 7 | `Code2Bench-2509`（54 题，Apache-2.0） |
| **物理学** | 计算物理、热流与凝聚态 | 8 | `SciCode-Verified v2`（Apache-2.0，物理重参数） |
| **天文学** | 天文光学、天体物理 | 6 | `SciCode-Verified v2`（Apache-2.0，物理与天文共计 15 组 / 40 子步骤） |
| **工程学** | 电力工程、工业工程、轨交与航空、道路与物流 | 15 | `MiniZinc Challenge 2024–2025`（MIT）与 `PGLib-OPF v23.07`（11 个交流最优潮流算例，CC-BY-4.0） |
| **医学** | 检验与代谢、重症与放疗 | 8 | `MedCalc-Bench-Verified`（2025，CC-BY-SA-4.0）与 `EchoSched` 放疗排程（MIT） |
| **金融学** | 公司与银行、量化与风控 | 8 | `FinanceBenchmark`（2025，MIT，重设测试参数） |

自 **0.3.0-dev** 起，新批次全面停用此前的自编编码题、2024 年 BigCodeBench、旧 MiniZinc 基准与合成两母线交流题（保留在开发仓库归档中用于历史批次只读回放），活动题库统一采用 2024–2026 开源原题或防记忆化重参数实例，三阶段累计开放 **67 / 126 / 182** 项（含 MiniZinc 24 个分级实例、医学与金融 53 项等）。各类材料的来源、修订版本和许可证在开发仓库中分别保留，以具体任务契约和验收结果为准。

科技解锁要求节点必做原题在同一冻结修订中全部通过独立隔离验收并可复现，同时满足前置条件、资金和年度机会限制；每年仅能尝试一次，失败同样消耗机会。科技分占总分 12%，达标数为 `min(52, 锁定总年限)`，全树覆盖率另列；既有设施建设门槛与部署规则继续有效。

## 结果边界

CivBench 当前属于未校准的合成城市 Dev/Beta 评测。程序测试通过、原题验收、提案可行、城市实际采用和模拟收益是不同层次的证据，需要分别报告。

科技树 `T1 → T4` 的递增结构依据学科前置、代码复杂度、实例规模与上游标签建立，尚未经过多模型实测通过率经验标定（`difficulty_calibrated: false`）；公开开源题与重参数改编亦不保证完全免受训练数据污染。现有结果不构成真实城市、临床、金融或工程能力认证，也不构成正式模型排名；综合能力字段 `capability_score` 仍保留为 `null`。同用户全盘可读的本地试跑不能宣称为正式防泄漏评测。
